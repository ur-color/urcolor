# @urcolor/ncs

[Natural Colour System](https://en.wikipedia.org/wiki/Natural_Color_System) notation for `@urcolor/core` — an opt-in plugin, not part of core.

```
S 1050-Y90R
NCS S 2030-Y90R
4030-B50G
S 0500-N
ncs(1050-Y90R)
```

## Installation

```bash
bun add @urcolor/ncs
```

Zero runtime dependencies beyond `@urcolor/core`.

## Usage

NCS parsing is **not** enabled by side effect. Call `registerNcsColor()` once, wherever your app boots:

```ts
import { Color } from "@urcolor/core";
import { registerNcsColor, toNcs } from "@urcolor/ncs";

registerNcsColor();

Color.parse("S 1050-Y90R");
toNcs(Color.parse("#eb7f7a")!); // "S 1050-Y90R"
```

`registerNcsColor()` returns an idempotent dispose function, so it is safe in test teardown:

```ts
const dispose = registerNcsColor();
// ...
dispose();
dispose(); // no-op, does not throw
```

Without calling it, `Color.parse("S 1050-Y90R")` returns `null`, exactly like any other unrecognised string. Registered parsers run after every built-in, so this package can neither shadow nor slow a standard notation.

## Notation

Both prefixes are optional and `ncs(…)` wraps any form. Parsing is case-insensitive.

| Form | Meaning |
| --- | --- |
| `S 1050-Y90R` | blackness 10, chromaticness 50, hue 90% from `Y` toward `R` |
| `1050-Y90R` | the same, prefix omitted |
| `NCS S 1050-Y90R` | the same, full prefix |
| `S 0580-Y` | an elementary hue, no second hue |
| `S 0500-N` | the neutral axis: blackness 05, no chromaticness |
| `ncs(1050-Y90R)` | functional wrapper around any of the above |

`S` marks the NCS 1950 standard edition. It is accepted and ignored; this package models that one edition.

Two rules return `null` rather than a wrong colour:

- **`blackness + chromaticness ≤ 100`.** Whiteness is the remainder, so `S 6050-Y` describes nothing.
- **Hue pairs must name adjacent hues.** The circle is `Y → R → B → G → Y`, and NCS holds that no hue resembles both members of an opponent pair, so `Y90R` is a colour while `R90G` and `Y50B` are not.

## Accuracy

**This is an approximation, and the numbers are on the label.**

NCS Colour AB holds the Natural Colour System as proprietary and publishes no open notation-to-sRGB mapping. The conversion here is a model fitted against 2,031 published values, not a specification. Anyone matching physical paint needs an official NCS fan deck.

Measured against the full reference set:

| | ΔE00 |
| --- | --- |
| mean | 1.65 |
| median | 1.41 |
| 95th percentile | 3.76 |
| worst | 10.6 |
| over 5 | 25 of 2,031 |

Two known weak spots, both structural rather than incidental:

- **Very dark near-neutrals.** The worst cases are around `S 8505-*`, where a colour is nearly black and ΔE00 magnifies small absolute differences.
- **Chromaticness above about 75.** The model's chroma curve peaks there and falls away after, so two chromaticness values produce the same lightness *and* chroma. No inverse can separate them. `toNcs()` takes the lower reading, so `S 0580-Y` round-trips as a slightly lower chromaticness while naming nearly the same colour.

The model works in Oklch, where NCS's blackness, chromaticness and whiteness behave close to linearly. Three forms were measured before settling on it:

| Form | mean ΔE00 | over 5 |
| --- | --- | --- |
| HSV scaling, 4 knots | 4.97 | 845 |
| HSV scaling, 16 knots | 3.52 | 409 |
| Linear mixture in Oklab | 4.84 | 739 |
| **Oklch, 16 knots** | **1.65** | **25** |

The mixture form is the one NCS's own definition suggests, a colour being `c%` pure hue plus `w%` white plus `s%` black. It fits worst, because NCS's percentages are judgements of perceptual resemblance rather than mixing weights.

Constants are regenerated by `bun run fit`, not hand-edited; `test/model.test.ts` pins the resulting error distribution.

## Serialisation

`toNcs(color)` returns exact two-digit values, for example `S 1347-Y83R`. They are **not** snapped to the NCS standard sample grid, so a result round-trips through `Color.parse()` but does not necessarily name a real, orderable NCS sample. Snapping would need NCS Colour AB's copyrighted sample list and would silently move the colour.

Colours outside what NCS expresses are clamped, so `toNcs()` always returns a notation. Round-trip the result and compare if you need to know whether it was faithful:

```ts
const notation = toNcs(color);
const faithful = deltaE(color.toObject(), Color.parse(notation)!.toObject(), "2000") < 2;
```

Across a sweep of the whole notation space, a round trip is mean ΔE00 0.19, 95th percentile 1.01, worst 6.17.
